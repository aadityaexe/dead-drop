# Dead Drop Server

This is the Express API for Dead Drop. It stores encrypted payloads, deletes drops when they expire or reach their read limit, and exposes lightweight health, status, and stats endpoints.

The server does not encrypt or decrypt user payloads. Encryption happens in the client.

## Setup

```bash
npm install
```

Create `.env`:

```env
PORT=3001
MONGODB_URI=mongodb://127.0.0.1:27017/dead-drop
```

Run in development:

```bash
npm run dev
```

Run normally:

```bash
npm start
```

## Endpoints

All endpoints are mounted under `/api`.

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/drop` | Create a new encrypted drop |
| `GET` | `/drop/:id` | Fetch encrypted drop data and update/burn the read count |
| `GET` | `/drop/:id/status` | Check whether a drop still exists without burning it |
| `GET` | `/stats` | Return in-memory display counters |
| `GET` | `/health` | Return API health and timestamp |

## Drop Storage

`models/Drop.js` stores:

- `ciphertext` and `iv`, both required Base64 strings.
- `salt`, present only for password-protected drops.
- `hasPassword`, `maxViews`, and `viewCount`.
- `expiresAt`, which is indexed with MongoDB TTL cleanup.

Drop IDs are UUID strings generated by the model.

## Read Behavior

Single-view drops are deleted with `findOneAndDelete` on the final read path. Multi-view drops increment `viewCount` until `viewCount >= maxViews`, then the final read deletes the document and returns the encrypted payload.

The API returns encrypted data only. The recipient browser is responsible for decryption.

## Limits And Middleware

- CORS currently allows all origins.
- JSON request bodies are limited to `1mb`.
- All `/api` routes use `express-rate-limit`.
- The limiter allows 100 requests per 15 minutes per IP.
- `securityHeaders` adds the project security headers.

## Deployment

`index.js` exports the Express app for Vercel serverless deployment. When not running on Vercel, the server connects to MongoDB and calls `app.listen(PORT)`.

In production outside Vercel, the server can also serve `client/dist` when `NODE_ENV=production`.
